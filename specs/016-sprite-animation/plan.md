## Design

### Overview

```
                         build (PC)                                       game (PC and 3DS)
assets/art/hero.png ───────────────── (tex3ds / copy) ──────▶ art/hero.png      load_texture("art/hero")
assets/art/hero.ase.json ─ nnh-assetc sprite ─▶ art/hero.nnhsprite              load_sprite_library("art/hero")
  (Aseprite export:        reads JSON + PNG header,  (the library block,               │ validate (shared) → copy with extras
   frames, tags, slices)   writes, validates, depfile  little-endian)                  ▼
                                                                    nnh::SpriteLibrary  (one block, tag "animation")
  or in code: SpriteLibrary::create({...}) + add_grid/add_clip/add_marker/add_state/add_transition
                                                                               │ read-only, shared
                                         entity member: nnh::SpriteAnimator anim_{library};  (≤ 64 B, no heap)
                                           update(): request(state) → anim_.update() → callback per notice
                                           draw():   gfx::draw(screen, texture, pos, anim_.draw_options())
```

The library is geometry, timing and the state machine; it never owns a texture. The animator is a plain value that
points at the library's block and advances only when the game calls `update()`/`advance()`.

### Public API (sketch)

```cpp
// <nnh/animation.hpp>: includes <cstdint>, "nnh/time.hpp" (Duration, Frames, FrameTime), "nnh/math.hpp" (Vec2,
// Region), "nnh/result.hpp", "nnh/detail/small_function.hpp", "nnh/detail/name_hash.hpp". Forward-declares
// DrawOptions (the game includes <nnh/gfx.hpp> to draw anyway).
namespace nnh {
struct DrawOptions;
namespace detail { struct SpriteBlock; }

// ---- Limits (FR-5; the spec's ceilings) ----
inline constexpr int kSpriteMaxFrames = 4096, kSpriteMaxClips = 256, kSpriteMaxClipLength = 256,
                     kSpriteMaxClipFrames = 8192, kSpriteMaxMarkers = 1024, kSpriteMaxStates = 32,
                     kSpriteMaxTransitions = 128, kSpriteMaxNameLength = 31, kSpriteMaxMarkersPerFrame = 8,
                     kSpriteMaxQueue = 4, kSpriteMaxNotices = 32, kSpriteMaxCrossings = 32,
                     kSpriteMaxCallbackDepth = 8;

/// 32-bit FNV-1a of a name: compare markers without strings (`case nnh::sprite_name("step"):`).
constexpr std::uint32_t sprite_name(const char* name) { return detail::fnv1a32(name); }

struct SpriteClipId  { std::uint16_t value = 0xFFFF; constexpr bool valid() const { return value != 0xFFFF; } };
struct SpriteStateId { std::uint8_t value = 0xFF; constexpr bool valid() const { return value != 0xFF; }
                       static constexpr SpriteStateId any() { return {0xFE}; } };

enum class SpritePivot : std::uint8_t { TopLeft, Center, BottomCenter };   // default pivot of a library
enum class SpriteMode : std::uint8_t { Loop, Once, Repeat, PingPong };
enum class SpriteDirection : std::uint8_t { Forward, Reverse };
enum class SpriteSwitch : std::uint8_t { Now, AtEnd, Never };             // transition rule kinds (FR-13)

struct SpriteLibraryDesc {          ///< every capacity is required (0 = none of that kind), no hidden default
    int frames = 0;                 ///< 1..kSpriteMaxFrames
    int clips = 0, clip_frames = 0, markers = 0, states = 0, transitions = 0;
    SpritePivot pivot = SpritePivot::TopLeft;   ///< default pivot of frames that don't give one (same as gfx::draw)
};
struct SpriteGridDesc {             ///< frames read row by row (FR-1)
    int frame_width = 0, frame_height = 0;
    int count = 0;                  ///< frames to add
    int columns = 0;                ///< 0: from image_width
    int image_width = 0, image_height = 0;   ///< 0: unknown (no fit check)
    int margin = 0, spacing = 0;
};
struct SpriteFrameDesc {
    Region region{};
    Vec2 pivot{-1, -1};             ///< in the untrimmed frame's pixels; negative = the library's default
    int offset_x = 0, offset_y = 0; ///< where the trimmed region sits in the untrimmed frame
    int source_width = 0, source_height = 0;   ///< untrimmed size; 0 = the region's (not trimmed)
};
struct SpriteClipDesc {
    const char* name = nullptr;     ///< unique in the library, 1..31 bytes
    const int* frames = nullptr;    ///< sheet frame indices; nullptr = the range [first, first + count)
    int first = 0, count = 0;       ///< count is also the length of `frames` (1..256)
    FrameTime frame_time = Frames{6};          ///< default duration of each frame (Duration or Frames)
    const FrameTime* durations = nullptr;      ///< optional, one per frame, overrides frame_time
    SpriteMode mode = SpriteMode::Loop;
    int repeat = 0;                 ///< Repeat: plays (≥ 1). PingPong: round trips (0 = forever)
    int pingpong_passes = 0;        ///< advanced: one-way passes, as Aseprite's tag `repeat`; overrides `repeat`
    SpriteDirection direction = SpriteDirection::Forward;
};
struct SpriteTransition {
    SpriteStateId from = SpriteStateId::any(), to = SpriteStateId::any();
    SpriteSwitch when = SpriteSwitch::Now;
    bool keep_time = false;         ///< the new state's clip continues at the same position and time
};
struct SpriteFrame { Region region; Vec2 pivot; Vec2 offset; };   ///< pivot in the untrimmed frame

class SpriteLibrary {               ///< move-only; one block (tag "animation") freed by the destructor
public:
    static Result<SpriteLibrary> create(const SpriteLibraryDesc& desc);
    SpriteLibrary() = default; ~SpriteLibrary();
    SpriteLibrary(SpriteLibrary&&) noexcept; SpriteLibrary& operator=(SpriteLibrary&&) noexcept;
    explicit operator bool() const;

    // Building (FR-1..FR-3, FR-8, FR-12, FR-13, FR-18). Data errors are returned, never asserted.
    Result<int> add_grid(const SpriteGridDesc& grid);          ///< index of the first frame added
    Result<int> add_frame(const SpriteFrameDesc& frame);
    Result<SpriteClipId> add_clip(const SpriteClipDesc& clip);
    Result<void> add_marker(SpriteClipId clip, int position, const char* name, int value = 0);
    Result<SpriteStateId> add_state(const char* name, SpriteClipId clip);
    Result<void> set_next_on_finish(SpriteStateId state, SpriteStateId next);
    Result<void> add_transition(const SpriteTransition& rule);

    // Queries (FR-5, FR-11)
    int frame_count() const; SpriteFrame frame(int index) const;
    DrawOptions draw_options(int frame, bool flip_x = false, bool flip_y = false) const;
    int clip_count() const; SpriteClipId find_clip(const char* name) const;   ///< linear over hashes
    const char* clip_name(SpriteClipId clip) const; int clip_length(SpriteClipId clip) const;
    FrameTime clip_duration(SpriteClipId clip) const;          ///< one play
    int state_count() const; SpriteStateId find_state(const char* name) const;
    const char* state_name(SpriteStateId state) const;
    std::size_t memory_used() const;
private:
    detail::SpriteBlock* block_ = nullptr;
};

struct LoadSpriteLibraryOptions {   ///< extra room in a loaded library for code (FR-16, FR-18)
    int extra_frames = 0, extra_clips = 0, extra_clip_frames = 0, extra_markers = 0, extra_states = 0,
        extra_transitions = 0;
};
/// Loads "<path>.nnhsprite" (made by the build from "<path>.ase.json"). Validated before use (FR-16).
Result<SpriteLibrary> load_sprite_library(const char* path, const LoadSpriteLibraryOptions& options = {});

// ---- Notifications (FR-8) ----
enum class SpriteNoticeKind : std::uint8_t { Marker, Looped, Finished, StateChanged };
struct SpriteNotice {               ///< 16 bytes
    SpriteNoticeKind kind = SpriteNoticeKind::Marker;
    SpriteStateId state{}, previous{};   ///< StateChanged
    SpriteClipId clip{};            ///< the clip the notice belongs to
    std::uint16_t position = 0;     ///< Marker: position in the clip
    std::uint32_t marker = 0;       ///< Marker: sprite_name() of its name
    std::int32_t value = 0;         ///< Marker: its value
};
struct SpriteNotices {              ///< view, valid until the next update()/advance() of any animator
    const SpriteNotice* data = nullptr; int count = 0;
    const SpriteNotice* begin() const { return data; } const SpriteNotice* end() const { return data + count; }
};
class SpriteAnimator;
using SpriteCallback = detail::SmallFunction<void(SpriteAnimator&, const SpriteNotice&)>;   // ≤ 16 B captures

// ---- The animator (FR-6..FR-10, FR-12..FR-14) ----
class SpriteAnimator {
public:
    SpriteAnimator() = default;                              ///< no library: queries answer "nothing"
    explicit SpriteAnimator(const SpriteLibrary& library);   ///< no clip yet
    SpriteAnimator(const SpriteLibrary& library, SpriteStateId start);   ///< state machine, in `start`

    // Clips (FR-6). Commands never fire notices; entered frames fire at the next update (FR-8).
    void play(SpriteClipId clip, bool restart = false);      ///< same clip, not finished, !restart: nothing
    void play(const char* name, bool restart = false);       ///< find_clip + play (a lookup)
    void play_from(SpriteClipId clip, int position);
    Result<void> queue(SpriteClipId clip);                   ///< ≤ 4; full: error, queue kept
    void clear_queue(); void stop(); void pause(); void resume();
    void set_frame(int position);                            ///< within the current clip
    void set_speed(float speed);                             ///< 0..64, rounded once to 1/4096; < 0 rejected
    float speed() const;
    void set_flip(bool flip_x, bool flip_y = false);
    void on_notice(SpriteCallback callback);                 ///< empty = none

    // State machine (FR-12, FR-13)
    void request(SpriteStateId state);                       ///< every update, from the game's conditions
    void force(SpriteStateId state);                         ///< bypasses the rules (death)

    // Clock (FR-7). update() = one 60 Hz frame; advance() = any span. Both × speed.
    SpriteNotices update();
    SpriteNotices advance(FrameTime time);

    // Queries (FR-6, FR-10, FR-13)
    bool playing() const; bool paused() const; bool finished() const;
    SpriteClipId clip() const; const char* clip_name() const;
    int position() const;           ///< in the clip's frame list
    int frame() const;              ///< sheet frame index (-1: no clip)
    Region region() const; Vec2 pivot() const; Vec2 offset() const;   ///< pivot: flip-adjusted, in the region
    FrameTime time_in_frame() const; float progress() const; int loops() const;
    SpriteStateId state() const; SpriteStateId previous_state() const; FrameTime time_in_state() const;
    bool flip_x() const; bool flip_y() const;
    DrawOptions draw_options() const;   ///< region, pivot, flips; the game adds layer, tint, opacity
private:
    const detail::SpriteBlock* block_ = nullptr;
    SpriteCallback callback_{};
    std::int32_t elapsed_ = 0, speed_ = 4096, state_time_ = 0;
    std::uint16_t clip_ = 0xFFFF, step_ = 0, cycles_ = 0, remainder_ = 0, serial_ = 0;
    std::uint8_t queue_[4] = {}, queue_size_ = 0, state_ = 0xFF, previous_ = 0xFF, pending_ = 0xFF, flags_ = 0;
};
} // namespace nnh
```

Notes on the API:

- **Names.** Types carry a `Sprite` prefix (spec answer: room for skeletal or property animation later). The loader
  is `load_sprite_library` (the spec's `load_animation` placeholder), matching the type it returns. The spec writes
  `gfx::DrawOptions`; the engine's type is `nnh::DrawOptions`.
- **Clip ids and state ids are values the game keeps** (`SpriteClipId run_ = lib.find_clip("run")`). Playing by name
  costs a linear scan over ≤ 256 hashes; the docs say so.
- **The update returns the notices** (the spec's "query of the last update's notifications"): a view into a
  module-wide scratch of `kSpriteMaxNotices` entries (512 B, `.bss`, linked only with the module), valid until the next
  `update()`/`advance()` of any animator. No list lives in the animator, which keeps it at 64 B. Animators are
  single-threaded (spec non-goal), so one scratch is enough. Calling `update()`/`advance()` from inside a callback
  asserts (Debug/Development) or is ignored with an error log (Release). FR-9 only allows commands there.
- **Drawing** (FR-10): `draw_options()` returns `{.region, .pivot, .flip_x, .flip_y}`. The pivot is
  `frame.pivot − offset` (the trimmed region's own coordinates), mirrored as `region.w − pivot.x` when `flip_x`
  (`region.h − pivot.y` for `flip_y`). `gfx::draw` keeps the pivot fixed in the drawn quad and mirrors the texture
  inside it (`gfx/draw_list.cpp`), so a trimmed frame and its untrimmed original land on the same pixels, flipped or
  not. The test compares the world rectangle of every opaque pixel.
- **Pivots** are stored in 1/16 pixel (int16), so a bottom-centre pivot of an odd-width frame (`x.5`) is exact.
- **Default animator** (no library): queries return "no clip" and commands assert. A default animator lets an
  entity be built before its library is loaded.

### Events introduced

None. Markers, loops, finishes and state changes are notifications delivered inside the owner's `update()`, through
the callback and the returned view (FR-8). A game that wants a bus event publishes its own from the callback
(`events::publish(Footstep{id_})`). A generic `AnimationMarker` event would be the anti-pattern of
[events.md](../../docs/architecture/events.md) and would arrive a frame late.

| Event | Published by | Payload | Typical listeners |
|-------|--------------|---------|-------------------|
| (game-defined, e.g. `Footstep{entity}`) | the game's animator callback | the game's struct | audio, particles, hit boxes |

### Semantics fixed by the plan

**Clock (FR-7, FR-14).** Durations are `FrameTime` ticks (1/4096 frame, from `<nnh/time.hpp>`). A `Duration` is rounded
once, half up, when the clip is added (`(ns·6144 + 12 500 000) / 25 000 000`); Aseprite milliseconds are rounded the
same way by the converter (`(ms·6144 + 12) / 25`: 100 ms = 24 576 ticks = 6 frames exactly). Speed is stored as ticks
per update (`int(speed·4096 + 0.5f)`, so 0.5 → 2048 and 1.5 → 6144 exactly). `update()` adds `speed_` ticks.
`advance(t)` adds `(t·speed_ + remainder) / 4096` and keeps the remainder (< 4096, a `uint16_t`), so neither drifts. A
frame ends when `elapsed ≥ duration`; the excess carries into the next frame, the next loop and engine-driven switches
(queue, at-end requests, next-on-finish). A command called by the game, or by a callback, starts the new clip at
elapsed 0.

**Sequences (FR-4).** A clip of `n` frames plays positions of a *cycle*. Its length is `L = n` for forward and reverse,
and `L = 2n − 2` for ping-pong (`n ≥ 2`), where position `p` shows clip index `p < n ? p : 2n − 2 − p`. Reverse
mirrors the index (`n − 1 − i`). The animator stores `step_` (position in the cycle) and `cycles_` (cycles completed;
`loops()`). A finite clip ends after a fixed number of shown positions, computed when the clip is added:

| Mode | Positions shown, then hold | `0 1 2 3` shows |
|------|----------------------------|-----------------|
| Loop | forever, `Looped` at every wrap | `0 1 2 3 0 1 …` |
| Once / Repeat n | `n_frames × plays` | `0 1 2 3` (hold 3) |
| PingPong forever | forever, `Looped` after each round trip | `0 1 2 3 2 1 0 1 …` |
| PingPong, `passes` P (round trips × 2) | `1 + P·(n − 1)` | P = 2: `0 1 2 3 2 1 0` (hold 0) |
| Reverse / PingPong reverse | the same counts, index mirrored | `3 2 1 0` / `3 2 1 0 1 2 3 2 …` |

A one-frame clip shows its frame; finite modes finish after `plays × duration` (ping-pong counts one frame per pass).
`Finished` fires when the last shown position's duration ends. The animator then holds that frame (`finished()`, not
`playing()`). `play()` of the same clip restarts it once it has finished (only a clip still playing is left alone).

**Ping-pong counts, checked against Aseprite.** Aseprite counts a ping-pong tag's `repeat` in one-way *passes*
(`doc/playback.cpp`: a ping-pong tag with no repeat plays 2 passes, `0 1 2 3 2 1 0`; each turn decrements the count;
with `repeat: 3` it plays `0 1 2 3 2 1 0 1 2 3`). The spec's code API counts round trips (`.repeat = n` → `P = 2n`,
FR-4: it ends on the first frame). The library stores passes, and the converter writes Aseprite's `repeat` as passes
unchanged, so an odd Aseprite count ends on the far frame exactly as in Aseprite (FR-17: "converted without changing
the result"). `SpriteClipDesc::pingpong_passes` gives code the same reach (FR-18: code and loaded clips behave
identically).

**Notices and their order (FR-8).** Entering a frame by `play`, `play_from`, `set_frame`, `force` or an immediate
state switch sets a *pending entry* flag. Nothing fires then. The next `update()`/`advance()` first fires the pending
entry, then advances time. Each frame crossing produces, in this order: `Looped` or `Finished` of the old position,
then (if the end triggers a switch) `StateChanged` and the switch, then the `Marker`s of the entered frame in the
order they were added. For each notice the callback runs at once, with the animator already showing that frame, and
the notice is appended to the returned view. A paused animator fires nothing.

**Re-entrancy (FR-9).** The animator keeps a change counter. If the callback changes the clip or state (play, queue
to a finished clip, stop, set_frame, request that switches, force), the update stops processing the old clip at once.
The remaining notices of the old clip and the rest of this call's time are dropped. The new clip's pending entry
fires in the same update with no time added, so a chain (a marker on idle's first frame plays attack, whose first
frame plays idle, …) is possible. At depth `kSpriteMaxCallbackDepth` (8) the chain stops with one `NNH_LOG_ERROR`, and
the animator stays on the last clip set. Commands on other animators are free. `update()` from a callback is misuse
(above).

**Crossing bound (FR-7).** One call crosses at most `kSpriteMaxCrossings` (32) frames and returns at most
`kSpriteMaxNotices` (32) notices. Markers per clip frame are capped at 8 (validated), so the entry of one frame always
fits. If a call would exceed either bound, Debug/Development assert. Release logs one error, computes the final
position directly (whole cycles skipped by division, then the remainder walked without notices), and keeps the
notices produced so far. The bound depends only on data and calls, so it is deterministic too.

**Queue (FR-6).** `queue(c)` appends `c` (`Result` error when 4 are queued; the queue is kept). When the current clip
finishes (once/repeat/finite ping-pong) or a looping clip wraps, the head of the queue starts with the carried time.
`queue()` on a stopped or finished animator plays at once (pending entry). `play()` clears the queue. `play()` and
`queue()` leave the state machine (`state()` becomes invalid).

**State machine (FR-12, FR-13).** States live in the library (name, clip, optional next-on-finish). Transition rules
are `(from|any, to|any, Now|AtEnd|Never, keep_time)`. `request(s)`:

1. `s` is the current state: nothing, and a pending at-end request is cleared (the game no longer wants to leave).
2. Otherwise the rule is the most specific match: `from→to`, then `from→any`, then `any→to`, then `any→any`; with no
   rule, `Now`. The search is a scan of ≤ 128 four-byte rules, and it runs only when the requested state differs
   from the current one and from the pending one.
3. `Now`: switch at once (pending entry; `keep_time` keeps `step_`, clamped to the new cycle, and `elapsed_`,
   clamped below the new frame's duration). `AtEnd`: remember `s` (replacing an earlier pending request), and switch
   at the end of the clip or of its current loop, carrying the leftover time. `Never`: ignored.

At the end of a finite clip, a pending request wins over next-on-finish, and next-on-finish wins over holding.
`force(s)` switches at once and clears the pending request. Every switch emits `StateChanged{state, previous}` and
resets `time_in_state()`. With no current state (after `play()`), `request` acts as `force`.

**Lifetime (FR-5).** Each library takes a 16-bit serial when it is created or loaded (never 0). Debug/Development keep
a table of live serials (1024 × `uint16_t` = 2 KB; a serial is picked so that its slot `serial & 1023` is free).
Every animator command and update asserts `live[serial & 1023] == serial`. Destroying the library clears the slot, so
an animator that outlives its library fails loudly at its next use. Release has neither the table nor the check
(constitution X: loud in Debug, free in Release). Moving a `SpriteLibrary` keeps its block, so animators stay valid.

### Data and memory

One block per library, from `mem::alloc(MemRegion::Heap, animation, …)`. The block layout *is* the `.nnhsprite` file
(as `.nnhmap` is for maps): a 64-byte header, then sections of fixed-size records, each 4-byte aligned and sized by
the header's capacities. A library built in code and a loaded one are the same data, and a later converter (spec 014
data assets, a non-goal here) can target the same format.

| Record | Bytes | Content |
|--------|-------|---------|
| `Header` | 64 | magic `NNHA`, version 1, file size, CRC-32 of the file (0 in memory), counts and capacities (6 × 2 × u16), default pivot, serial (memory only) |
| `FrameEntry` | 16 | region x, y, w, h (i16), pivot x, y (i16, 1/16 px, untrimmed frame), offset x, y (i16) |
| `ClipEntry` | 52 | name (32, NUL-padded), hash, first clip frame (u16), length (u16), mode, direction, passes or plays (u16), end step and end cycle (u16 × 2), cycle duration (i32) |
| `ClipFrameEntry` | 12 | sheet frame (u16), first marker (u16), marker count (u8), duration (i32 ticks) |
| `MarkerEntry` | 8 | name hash (u32), value (i32); sorted by clip frame |
| `StateEntry` | 40 | name (32), hash, clip (u16), next-on-finish (u8) |
| `TransitionEntry` | 4 | from, to (u8, 0xFE = any), when, keep_time |

Examples: the example's hero (40 frames, 8 clips, 64 clip frames, 6 markers, 6 states, 12 rules) ≈ 2.2 KB; the
platformer's player (4 frames, 4 clips, 5 clip frames, 2 markers, 4 states) ≈ 0.6 KB; the ceilings ≈ 187 KB. Names
are kept for logs and `clip_name()`; marker names are hashed only (documented: the converter and `add_marker` reject
two different names with the same hash in one library).

**Animator**: 64 B on 3DS (block pointer 4, `SmallFunction` 24, three `int32` 12, five `uint16` 10, queue 4, five
`uint8`, padded), about 80 B on PC; `static_assert(sizeof(SpriteAnimator) <= (sizeof(void*) == 4 ? 64 : 96))`. 512
animators take 32 KB. **Module statics**: 512 B notice scratch, plus 2 KB live-serial table in Debug/Development.
Libraries still alive after `nnh::shutdown()` show up in the leak report under `animation`. The example and the docs
destroy them first, as the platformer does with maps.

### The frame clock in `<nnh/time.hpp>` (FR-14, XI)

`Frames` and `FrameTime` (with `kMaxFrameTime`, the `Duration` conversion and the invalid marker exactly as plan 015
specifies) are declared in `<nnh/time.hpp>`. They are `constexpr` and header-only, so `hello` gains no code.
[Plan 015](../015-tweens-and-timers/plan.md) carries the matching "Amended by plan 016" note: whichever spec is
implemented first adds them there, with `tests/time/test_frame_time.cpp`. `<nnh/tween.hpp>` already includes
`time.hpp`, so tween code is unchanged either way.

`detail::fnv1a32` (constexpr, in the new `nnh/detail/name_hash.hpp`, no includes beyond `<cstdint>`) is the one
FNV-1a 32 of the engine. Plan 014's `core/path_hash` uses the same function when it lands, and `nnh-assetc` compiles
it too.

### Aseprite conversion (FR-16, FR-17, D31)

**Format facts, checked on 2026-11-22** against Aseprite's own exporter and player (`src/app/doc_exporter.cpp`,
`src/doc/playback.cpp`, `src/doc/anidir.cpp` on the `main` branch, MIT-licensed; read, not copied):

- Tags: `{"name", "from", "to", "direction"}` plus `"repeat"`, which is **written as a string** (`"repeat": "3"`) and
  **only when it is > 0**. Absent means the tag loops. Tag user data adds an optional `"color"` (hex string) and
  `"data"`; both are ignored. The converter accepts `repeat` as a string of decimal digits and, leniently, as a whole
  number.
- Directions: `forward`, `reverse`, `pingpong`, `pingpong_reverse`.
- Ping-pong: turning frames are not repeated, and `repeat` counts one-way passes (above). The spec's sequences
  (`0 1 2 3 2 1 …`, the reverse one starting `3 2 1 0 1 2`) match.
- Frames: `"rotated": false` is always written; `"trimmed"`, `"spriteSourceSize"` `{x,y,w,h}`, `"sourceSize"`
  `{w,h}`, `"duration"` (integer milliseconds). In the Hash layout each frame is keyed by its file name, in export
  order; in the Array layout each object has a `"filename"`.
- Slices: `{"name", "keys": [{"frame", "bounds" {x,y,w,h}, "center"?, "pivot"? {x,y}}]}`. The pivot is taken as
  **relative to the key's bounds**. Aseprite's slices page shows `center` that way (`bounds` 118,118 and `center`
  5,5). The converter adds `bounds.x/y`. This is inferred, not stated by the docs; risk below.
- Meta: `"image"` is the PNG's file name without folders (written only when a sheet file is set), plus `"size"`
  `{w,h}` and `"format"`.

**Command**: `nnh-assetc sprite <in.ase.json> <out.nnhsprite> --assets <root> [--depfile <d>]`. It reads the JSON
through the existing bounded reader, checks that `meta.image` equals `<name>.png` beside it and that `meta.size`
equals the PNG header (`png_size.cpp`), and builds the model:

- frames in file order (Hash or Array); `rotated: true` → error; `spriteSourceSize.w/h` must equal `frame.w/h`;
  offset = `spriteSourceSize.x/y`; the region lies inside `meta.size`; duration 1..65 535 ms;
- clips from tags not starting with `@`: `from ≤ to < frames`, ≤ 256 frames, name 1..31 bytes, unique (and unique
  hash); forward/reverse with `repeat` 1 → Once, n → Repeat n, absent → Loop; ping-pong → passes = `repeat` (absent →
  forever); every clip frame takes its frame's own duration;
- marker tags `@name` or `@name=value` (value an integer in −32768..32767, an extension within FR-8's "optional
  small integer"): the marker goes on every clip frame showing a frame in `from..to`, in every clip;
- no clip tags → one clip `default`, all frames forward, looping;
- slice `pivot`: first key's `pivot` (+ bounds origin), or its bounds' centre-bottom; it sets every frame's pivot.
  Without it the pivot is top-left (the library default, same as `gfx::draw`);
- capacities = exactly the counts; the bytes are written and then checked with core's `validate_sprite_library` before
  the file is written.

Errors are `file:line: reason`. The JSON reader gains the line of each value (`Node::line`, 4 bytes, `Ref::line()`),
and `Problem` gains a line. The Tiled converter keeps printing `file: reason` (unchanged; it may adopt lines later).
The depfile lists the JSON and the PNG.

**Build**: in `cmake/nnh_assets.cmake`, `<name>.ase.json` → `<name>.nnhsprite` through a `_nnh_add_sprite_step`
with a depfile in `<game build>/nnh_sprites/`. The PNG keeps its normal image step. `*.ase` and `*.aseprite` (the
editor's own files, if kept in the assets folder) are not packed, like `.tsj`. The converter is requested when the
folder has a `.tmj` **or** a `.ase.json`; `nnh_assetc_command`'s configure error names whichever kind the game has.
The `.ase.json` match comes before every generic rule, so it owns the suffix in every game.

**Coordination with plan 014 (D29).** In a game with `DATA_SCHEMA`, every asset "whose extension the asset pipeline
doesn't own" goes through `nnh-assetc data`. D31 adds `.ase.json`, `.ase` and `.aseprite` to the owned set, and
`nnhsprite`, `ase` and `aseprite` to the data keys the schema program refuses. The routing order in
`nnh_assets.cmake` is: not-packed editor files → `.tmj` → `.ase.json` → images → sounds → data (schema games) → copy.
Whichever of 014 and 016 is implemented second applies this (task T7.6). Neither plan's files change shape.

### Performance (AC-7)

The normal update of one animator does a pending-flag test, `elapsed += speed`, and one compare against the current
clip frame's duration (one 12-byte record, usually cached by the previous frame), with no crossing in most frames.
A request with no change is two byte compares. Estimate on the Old 3DS ARM11 (268 MHz): ≈ 40 cycles in the common
case, ≈ 150–250 cycles on a crossing with a marker and a callback. 512 animators with one crossing in six frames ≈
40–60 k cycles ≈ 0.15–0.25 ms, under the 0.5 ms target. Debug/Development add the live-serial check (≈ 5 cycles). If
the target is missed, the fixes in order are: cache the current frame's duration in the animator (if a padding byte
pair allows it), skip the callback dispatch when it's empty, then report the real number and agree the docs' target
with the maintainer.

## Risks and alternatives

- **Aseprite details not confirmed by a real export.** The repeat type, directions and ping-pong counting are
  confirmed from Aseprite's source. The slice pivot's origin is inferred (relative to bounds). The fixtures follow
  that, and the docs ask users to report a mismatch. If the maintainer has Aseprite, one real export added to
  `tests/data/aseprite/` (T7.3) closes this. A wrong guess only shifts the pivot, and fixing it is one line in
  `aseprite_slices.cpp`.
- **Aseprite's ping-pong counting differs from the spec's code API** (passes vs round trips). Answered by storing
  passes, with round trips in the code API and an advanced `pingpong_passes` field. If the maintainer would rather
  count passes everywhere, only `SpriteClipDesc`'s doc and one line change.
- **Notices view tied to one module scratch.** A game that keeps the view across two updates reads the newer one.
  This is documented in the header. The alternative, a 32-entry list per animator, would cost 512 B per animator, and
  a caller-provided buffer would make every `update()` call heavier to write.
- **Dropping the rest of an update's time when a callback switches clips** is simple and deterministic, but it loses
  up to one frame of time in that rare case. The alternative, carrying it into the new clip, complicates the crossing
  bound and the depth logic. Engine-driven switches (queue, at-end, next-on-finish) do carry, and those are the cases
  where exact timing matters.
- **Animator size on PC** (about 80 B, because `SmallFunction` is 32 B there) doesn't matter: the 64 B target is for
  the 3DS, and it is `static_assert`ed in 32-bit builds.
- **Lifetime detection** is Debug/Development only and assumes fewer than 1024 libraries alive at once (asserted).
- **The PNG must obey the texture rules** (power-of-two sides on 3DS). The existing image check reports it, and the
  docs tell users to export with Aseprite's "power of 2" constraint or a fixed width.
- **Alternative for markers: one engine bus event.** Rejected (generic event anti-pattern, a frame late).
  **Alternative for the state machine: Unity-style parameters.** A non-goal. **Alternative clock: milliseconds.**
  Rejected: frames are what replays count, and spec 015 already defines this clock.

## Stage refinements and results (implementation, 2026-11-22)

Deviations found while building, as plan 012 records them. None changes the public API sketched above beyond the
additions listed.

**Stage 0 results.** T0.2 and T0.3 were already done on main (`Frames`/`FrameTime` in `<nnh/time.hpp>` by spec 015,
`detail::fnv1a32` by spec 014). Baselines (WinLibs GCC 16, devkitARM): pc-release `hello.exe` text 129 376, data
21 988, bss 207 568 (file 277 503 bytes); 3ds-release `hello.elf` text 216 260, data 28 328, bss 102 584. A one-line TU
with `<nnh/events.hpp>`: 7 636 preprocessed lines, ≈ 0.43 s `-fsyntax-only`. Build-time measurements of hello edits
were not repeated (no build-system change touches hello).

**Stage 1 refinements.** The header stores the offsets of the five sections after the frames (`offset[5]`, u32;
frames start at 64) and keeps the serial in bytes 6–7, outside the CRC (memory only; the validator ignores it).
`ClipFrameEntry` puts the duration first (no padding inside). Pivot/offset helpers are a pure header,
`sprite_frame_math.hpp`. `SpriteLibraryAccess` (internal header) adopts loaded blocks and gives tests the block.

**Stage 3–5 refinements.** The animator has one more byte than sketched, `changes_` (a change counter for
re-entrancy, in what was padding); the callback comes first for alignment: 64 bytes on 3DS (`static_assert`ed, the
3DS build checks it), 80 on PC. The walk over crossings is its own file (`animator_walk.cpp`). Fixed details: a
finished clip holds its last frame with `time_in_frame()` = that frame's whole duration; `set_frame` restarts the loop
count (a finite clip could otherwise never reach its end); `force()` of the current state only clears a waiting
request; the start state of `SpriteAnimator{lib, state}` fires its frame's markers but no `StateChanged`; a state
change made during an update (at-end, next-on-finish) starts `time_in_state()` at the carried time; a command from a
callback that changes the clip also drops the rest of the update's time when it happens during the pending entry.
Release's bound path skips whole loops by division and caps silent steps at 65 536 per call (then drops the rest of
the time: only pathological chains of tiny finite clips reach it). `add_marker` can't refuse two different marker
names with one hash (names aren't stored); the converter refuses them.

**Stage 6 refinements.** "Code vs file" is covered by `test_sprite_load.cpp` (a code-built library written as a file
plays the same frames and notices) and `test_sprite_aseprite.cpp` (the converted fixture, end to end); the mini-fuzz

## Console bench refinement (2026-11-22)

**Measured.** First run of `examples/animation`'s bench on an Old 3DS (Development build, GCC 16 `-O2`): 512 animators
avg **0.892 ms**, worst **1.389 ms** per frame, over the 0.5 ms target: ≈ 1.7 µs (≈ 470 cycles at 268 MHz) per
animator. Behaviour was right (self-check `512F027F`, the PC's).

**What was hot.** No division or 64-bit helper was on the update path (`__aeabi_idiv` only in the silent cycle skip,
`__aeabi_l2d/l2f` only in `progress()`; `advance()`'s `% 4096` compiles to shifts). The cost was calls and memory:

- an update made ≈ 7 out-of-line calls before its first compare: `update` → `run` → `notice_scratch()`,
  `library()` → `sprite_serial_live()` (Development), `walk()` → `clip_frame()` → `clip()` → `sprite_clip_index()`,
  each a separate object file (no LTO), so nothing was inlined; a request made `library()` → `sprite_serial_live()`;
- the fields an update reads and writes sat at bytes 24–60 of the 64-byte animator (the callback came first), so every
  update touched both 32-byte ARM11 cache lines of its animator; 512 animators are 32 KB, twice the Old 3DS's 16 KB
  L1 data cache, so each line is a miss to FCRAM every frame (and a write-back).

**Changes** (behaviour unchanged: every test passes as it was, self-check checksum still `512F027F`; 64 bytes on 3DS,
80 on PC as before):

- `run()` has a fast path: no pending entry → add the time; if it stays inside the current frame, return, with no
  `AnimPass`, no `walk()` and no call. Crossings take the old loop (time already added).
- Inline in the internal headers: `Access::library()` (the misuse cases moved to an out-of-line `library_misuse()`),
  `clip()`, `clip_frame()`, `notice_scratch()` (the scratch is `detail::g_notice_scratch`),
  `sprite_serial_live()` (the live table is `detail::g_sprite_live`), `sprite_cycle_length()` and
  `sprite_clip_index()` (`sprite_sequence.hpp`, still pure).
- The animator's members are reordered: what `update()`/`request()` touch first (`block_`, times, clip, step,
  cycles, remainder, serial, state bytes, flags: exactly 32 bytes on 3DS), then the queue and the callback, read only
  when a clip ends or a notice fires. Private members only: no API change, but the layout changes (rebuild games).
- `sprite_resolve_rule()` ranks the rules in one pass (stopping at an exact rule) instead of four scans; the same rule
  wins (new test `of_two_rules_of_the_same_shape_the_first_wins`).

**Results.** PC microbenchmark (the bench's workload, 512 animators × 20 000 frames, pc-release, same machine): avg
21.6–22.6 µs → 12.2–12.9 µs per frame (best 18.3 → 9.1 µs), the same frames and notices (identical checksum of every
frame and notice count). 3DS Development code: the common update is now ≈ 60 instructions with no call (a request
with no change ≈ 25). The console number after the change is pending a re-run (`nnh run animation --script
examples/animation/tests/check.nnhs`, the "animation bench:" line); the target itself is the maintainer's call.

**Not done (options).** If a game's animators must fit one cache line each, the array must be 32-byte aligned (an
8-byte aligned `new[]` puts the hot half across two lines in 3 cases out of 4): `alignas(32)` on `SpriteAnimator`
would guarantee it but pads every entity that embeds one, so it's left to the maintainer. Caching the current frame's
duration in the animator would save the clip and clip-frame reads but has no room in the 32 hot bytes.
