## Design

### Decision D22 — packaging is a build step around devkitPro's

`.3dsx` stays devkitPro's (`ctr_generate_smdh` + `ctr_create_3dsx`). The `.cia` is made by makerom
from the same ELF, the same SMDH, a banner from bannertool and the same assets folder as romfs. The tools
are prebuilt official releases downloaded on demand (pinned), so a contributor needs nothing new until a
game asks for a `.cia`. Alternative rejected: building the tools from source at configure (slow, needs
their dependencies).

### `nnh_add_game()` (cmake/nnh_game.cmake)

```cmake
nnh_add_game(audio
    SOURCES main.cpp
    ASSETS assets
    TITLE "NNHGE Audio"  DESCRIPTION "Sound effects, streamed music and the mixer"
    AUTHOR "NNHGE contributors"  VERSION 1.0.0  ICON icon.png         # 48x48 PNG; default: NNHGE icon
    CIA UNIQUE_ID 0xE0A01                                              # turns the .cia on
        [PRODUCT_CODE CTR-H-AUDI]  [BANNER banner.png]  [BANNER_AUDIO banner.wav])
```

- `VERSION` (default `0.1.0`): `major` 0–63, `minor` 0–63, `micro` 0–15 (the CIA title version fields).
- `CIA` is a keyword that starts a group of options (`cmake_parse_arguments` with the group's keys).
  `UNIQUE_ID` is required with it; `PRODUCT_CODE` defaults to `CTR-H-` + the first 4 letters/digits of
  the target, upper case.
- The game also gets `NNH_GAME_TITLE` as a compile definition; `AppConfig::title` defaults to it, so the
  simulator window shows the game's title without repeating it in code (FR-1).

### Checks (CMake scripts run as build steps, with ctest cases)

| Script | Checks | Runs |
|--------|--------|------|
| `cmake/nnh_check_icon.cmake` | PNG, exactly 48×48 | every 3DS build of a game (cheap, cached by stamp) |
| `cmake/nnh_check_package.cmake` | unique ID in `0x00300`–`0xF7FFF`; product code `CTR-[A-Z]-[A-Z0-9]{4}`; version ranges; title ≤ 64, description ≤ 128, author ≤ 64 characters (UTF-8 aware) | configure, for games with `CIA` (fails at configure, naming the field) |
| `cmake/nnh_check_banner.cmake` | banner PNG exactly 256×128; banner audio a PCM WAV (16-bit, mono/stereo) of at most 3.0 s | the `.cia` build step |

### Tools (`cmake/nnh_ctr_tools.cmake`)

`nnh_ctr_tools()` — called only when a game has `CIA` (implementation note: the download became a build step, target `nnh_ctr_tools`, run by the first `.cia` build — with a `CIA` example in the repository, a configure-time download would have hit every 3DS configure):
- cache variables `NNH_MAKEROM` and `NNH_BANNERTOOL`: if set (offline, macOS), they are used as is;
- else download into `build/<preset>/_tools/` with `file(DOWNLOAD ... EXPECTED_HASH SHA256=...)` (reusing
  the CA-bundle fallback of `nnh_sdl3.cmake`) and extract:

| Tool | Windows | Linux x86-64 |
|------|---------|--------------|
| makerom v0.19.0 (3DSGuy/Project_CTR) | `makerom-v0.19.0-win_x86_64.zip` `88df4455…db0` | `makerom-v0.19.0-ubuntu_x86_64.zip` `287b809d…97e` |
| bannertool 1.2.3 (carstene1ns/3ds-bannertool) | `bannertool-1.2.3-windows.zip` `d0f277bd…3c4` | `bannertool-1.2.3-linux.tar.gz` `748519d2…55` (glibc 2.39+) |

(full hashes in the script.) macOS or another host: a clear error asking for `NNH_MAKEROM`/`NNH_BANNERTOOL`.

### The `.cia` (`cmake/nnh_cia.cmake`)

1. `bannertool makebanner -i <banner.png> -a <banner.wav> -o <game>.bnr` (after the banner check).
2. `makerom -f cia -o dist/<game>/<game>.cia -target t -exefslogo -elf <game>.elf -rsf cmake/3ds/nnhge.rsf
   -icon <game>.smdh -banner <game>.bnr -major/-minor/-micro <version> -DAPP_TITLE=… -DAPP_PRODUCT_CODE=…
   -DAPP_UNIQUE_ID=… -DAPP_ROMFS=<binary dir>/assets` (romfs line dropped when the game has no assets).
3. `cmake/3ds/nnhge.rsf`: our own RSF (written from makerom's documented format, not copied): category
   Application, SD application, 64 MB system mode, 268 MHz, the services the engine uses (APT, fs, gsp,
   hid, ir:rst, dsp, cfg, ptm, ndm, soc for 3dslink logs), file system access for the SD card and the
   romfs root `$(APP_ROMFS)`.
4. Targets: `<game>_cia` (not part of `all`) and `<game>_dist`, which copies the `.3dsx` (and builds the
   `.cia` when configured) into `build/<preset>/dist/<game>/`; a global `dist` target builds every game's.

### Default art (FR-2, FR-3)

`scripts/make_package_art.py` (Pillow) draws original NNHGE art into `cmake/3ds/`: `default_icon.png`
(48×48), `default_banner.png` (256×128) and `default_banner.wav` (a ~1.5 s jingle synthesized like the
audio example's). The outputs are committed.

### Example

`examples/audio` gets `VERSION`, its own `icon.png`/`banner.png`/`banner.wav` (from its `make_sounds.py`
plus a small drawing script) and `CIA UNIQUE_ID 0xE0A01` (inside the homebrew range, printed by the build).
The other examples use the default icon.

## Test strategy

| Requirement | Verified by |
|-------------|-------------|
| FR-1 | ctest: configure a tiny game project with `VERSION`/`CIA` and read back the values passed to makerom (dry run variable); the simulator title (screenshot of `examples/audio`) |
| FR-2 | ctest `icon_check_*` (48×48 ok, 64×64, not PNG); `hello` on the 3DS with the default icon (maintainer) |
| FR-3, FR-4 | `examples/audio` `.cia` installed with FBI: banner, jingle, assets, music, exit to HOME, uninstall (maintainer) |
| FR-5 | ctest `package_check_*` (ID below/above the range, bad product code, version out of range, long title in ASCII and in UTF-8), `banner_check_*` (wrong size, 4 s sound, 24-bit sound) |
| FR-6 | a configure without `CIA` has no `_tools/` folder (ctest on a fresh build dir of the tiny project); tool hashes checked by `file(DOWNLOAD)`; Linux `.cia` built on VM 120 |
| FR-7 | `dist/<game>/` holds the files after `cmake --build --preset 3ds-release --target dist` |

## Risks and alternatives

- **RSF correctness** (services, permissions): a wrong RSF installs but crashes or can't reach a
  service. Mitigation: start from makerom's documented fields, test each engine feature in the `.cia`
  (assets, audio, saves, 3dslink logs in Development) on hardware.
- **Unique ID collisions** with other homebrew: the build prints the ID; the guide explains how to pick
  one (random in the range) and where lists of used IDs are kept.
- **bannertool's Linux binary needs glibc 2.39+** (Ubuntu 24.04 is fine); older hosts use `NNH_BANNERTOOL`.
- **MSYS2 CMake downloads** (3DS builds on Windows run in devkitPro's MSYS2): the CA fallback of the SDL3
  fetch is reused; if it still fails, `NNH_MAKEROM`/`NNH_BANNERTOOL` work offline.
- **Title length in characters**: CMake counts bytes; the check counts UTF-8 lead bytes instead.
